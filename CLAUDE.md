## Committing
Use conventional commits with the following template
<type>[optional scope]: <description>


## Always
- Keep the commit small and focused on sizable changes
* Inspect relevant code before making changes.
* Follow existing project conventions unless instructed otherwise.
* Prefer correctness over cleverness.
* Keep changes focused on the requested task.
* Use ASD-STE100 Simplified Technical English for documentation and user-facing responses.
* Keep comments short and explain why, not what.
* Prefer code that is clear without comments.
* Verify changes with the appropriate build, test, or validation tools when available.
* State clearly when a change could not be verified.
* Preserve existing user changes.
* Check relevant references before changing or removing assets, APIs, or configuration.

## Never
- Never include co authored by when making a commit
* Never invent APIs, assets, configuration values, commands, or project conventions.
* Never claim that code was built, tested, or verified when it was not.
* Never make unrelated changes while completing a task.
* Never change code identifiers to satisfy documentation language rules.
